# 演示 Runbook：怎么跑、问什么、看哪里

这份是"把项目演给别人看"的操作手册。装依赖、填 key 见
[README 快速开始](../README.md#快速开始)，这里只讲**跑起来之后**的事。

演示规模（示例问题的根据都在这里）：知识库 32 文档 / 8 个 SKU，横跨
耳机（4）· 冲锋衣（2）· 洗衣机（2）三个品类；订单数据里 `u1001` 有两笔
（一笔在途可查物流，一笔已完成可走售后）。

## 一、三条命令

### ① 演示前 30 秒自检（零成本、不联网）

```bash
cd <项目根>
.venv/Scripts/python.exe -m app.agent.webui --e2e
```

期望最后一行是 `e2e 通过：…`。这条用 `streamlit.testing.v1.AppTest` 在同进程里
执行整个前端脚本，断言"脚本真的跑起来了、一问一答进了会话、侧栏把轨迹画出来了"。
**演示前跑一次，比当场翻车强。**

### ② 浏览器演示（主战场）

```bash
cd <项目根>
.venv/Scripts/python.exe -m streamlit run app/agent/webui.py
```

浏览器没自动打开就访问 `http://localhost:8501`。

> ⚠️ **进去第一件事：点侧栏「预热模型」**，等十几秒。
> 不点的话第一轮检索要等约 13 秒（BGE-M3 首次加载，实测 `retrieval_ms=14973`），
> 看着像卡死。预热之后每轮 500ms 上下。

### ③ 终端演示（备选：网速差、或想直接复制文字记录时）

```bash
cd <项目根>
.venv/Scripts/python.exe -m app.agent.cli
```

`/trace` 看本轮内部状态 · `/history` 看记忆几轮 · `/new` 换会话 · `/exit` 退出

## 二、演示脚本（按支路排，讲 5 分钟）

**"来源"一列是诚实的标价**：✅ 真实 LLM 实测过的，其余来自 50 条评测集
（[docs/01](01_rag_knowledge_base.md) §七，hit@5 = 100%，但它测的是检索不是全链路）
或 mock 数据（确定）。

| # | 你输入 | 会看到什么 | 讲什么 | 来源 |
|---|---|---|---|---|
| **第 1 幕：实时数据不走 RAG** | | | | |
| 1 | `SKU-10001 现在多少钱` | 799 → 活动价 599，还能叠新人券 579 | 价格/库存是**实时状态**，只经 Function Calling，不进知识库；RAG 里的 spec 只是带时间戳的快照 | ✅ 实测 |
| 2 | `ORD-20260901-001 的物流到哪了` | 顺丰单号 SF1388001122334 | 工具层返回结构化结果，模型只负责转述 | mock |
| 3 | `SKU-10003 有货吗` | 断货，9-20 补货 | **坦诚报缺货，不编一个"有货"** | mock |
| **第 2 幕：RAG 商品咨询** | | | | |
| 4 | `SKU-10001 续航能用多久` | 引用 spec 块作答 | 混合检索：向量管"意思像"，BM25 管"字面准"（型号这种字符串向量排不上） | 评测集 |
| 5 | `冲锋衣可以用柔顺剂洗吗` | 说清为什么不能 | 检索为空时不硬编，走"暂无相关信息"兜底 | ✅ 实测 |
| **第 3 幕：口碑域（两边都讲）** | | | | |
| 6 | `SKU-10001 这个耳机口碑怎么样` | 好评 82% / 差评 12%，**末尾给适用建议** | 这就是第 8 个意图 `review_consult` 存在的理由：评价是口语化文本，和商品详情混一库会污染相似度。**别只挑好评说** | ✅ 实测，效果最好的一轮 |
| 7 | `这款耳机有什么缺点` | 只挑差评说 | 测**省主语的追问**：靠会话里的"话题商品锚点"接上上一句 | 评测集 |
| **第 4 幕：对比 / 推荐** | | | | |
| 8 | `SKU-10001 和 SKU-20001 哪个好` | 逐项对比 + 倾向性建议 | 槽位进查询（拼成"X 与 Y 对比 参数"），比裸话术召回准 | 评测集 |
| 9 | `预算三百以内有什么入门耳机` | 推荐 + 主动反问缩小范围 | 推荐类意图要"给完还问一句"，否则用户还得自己组织下一轮 | 评测集 |
| **第 5 幕：政策** | | | | |
| 10 | `七天无理由退货要满足什么条件` | 走 `policy_knowledge` | 三个知识域里的第三个；`faq/guide/policy` 的 `product_id` 是空串，所以锚点只能重排不能独占过滤 | 评测集 |
| **第 6 幕：写操作确认门（最该展示的一幕）** | | | | |
| 11 | `ORD-20260908-002 的冲锋衣尺码偏大，我要退货` | 提案，**但模型自己不写"请确认"** | 写操作走「提案 → 用户确认 → 执行」。让模型在正文里征求确认会让系统错过确认流程 | mock |
| 12 | `确认` | 工单号 AS-… | 侧栏跳出「待确认的写操作」→ gate=`accept`，工具表里出现 `apply_after_sale` | mock |
| 12' | 换 `算了不换了`（拒绝路径） | "已为您取消本次申请" | 确认门放在**意图识别之前**：纯关键词判定，不让 LLM 猜"算了"是什么意思 | mock |
| **第 7 幕：兜底（"不硬猜"）** | | | | |
| 13 | `转人工` | 转接 + 排队位次 + **对话摘要** | 人机切换不转述 = 让用户重问一遍 | 评测集 |
| 14 | `你说的不对` → 再一句表达不满 | 第 2 次自动转人工，附摘要 | 连续不满 ×2 主动转人工，且**转人工那轮也写进会话历史** | 可能要试两三句 |
| 15 | `你好呀` | 闲聊，且能聊到上文 | 闲聊走独立支路，不检索 | ✅ 实测 |

**最后一幕：把侧栏当主角。** 指着召回块表格讲三件事：

1. `rrf_score` 是 **RRF 融合分 × doc_type 权重**，只能跟 `SCORE_THRESHOLD` 比，
   **不是相似度**——别把它读成"相关度只有 0.03，很低"。
2. 「被引用」列是**代理指标**（字符 4-gram 重叠率，已扣掉本轮各块共有的样板文字）。
   实测同一条 query 前后跑两次，召回完全相同，引用块数却是 1 和 3，差异全在措辞。
   所以它度量的是"模型抄了多少字面"，**方差比绝对值更值得注意**。
3. `outcome` 字段（answered / no_info / llm_fail）把 LLM 故障挡在引用率分母之外——
   否则网络一抖就把基础设施故障算成检索质量问题。

## 三、别在演示现场赌这两条兜底

**低置信澄清**（要模型自己给出 < 0.6 的置信度）和 **检索为空**（要检索分低于 0.012，
而阈值很低，问库里没有的东西通常还是能召回点东西）——**这两条不容易演出来**。
它们的逻辑已被 `graph.py` 自测和 `trace_view` 的标签字典覆盖。

讲的时候说"这两条有实现、但演示现场不好触发"就行，比当场翻车强。

## 四、故障对照表

| 现象 | 原因 | 处理 |
|---|---|---|
| 每轮都回"抱歉，我这边刚才没能连上后台服务" | LLM 请求出不去（网络 / 代理） | 见 [`.env.example`](../.env.example) 的代理说明；改完 `.env` 要重启进程 |
| 第一轮卡十几秒 | BGE-M3 首次加载 | 点侧栏「预热模型」 |
| 侧栏召回块数为 0 | 正常兜底，不是 bug | 换成第二节表里的话术 |
| `Address already in use` | 上次进程没退干净 | 加 `--server.port 8502` |
| 打开首页返回 200 但页面空白 | 脚本要等 websocket 连上才执行 | 别用 `curl` 判活，用 `python -m app.agent.webui --e2e` |
| 侧栏轨迹显示的还是上一轮 | — | 正常情况每轮结尾会 `st.rerun()` 刷新；若仍不刷，点「结束会话」重开 |
